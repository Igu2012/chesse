# Chesse

Chesse is a compact web chess dashboard inspired by modern online chess platforms. It combines a Node.js/Express API, a static HTML/CSS/JavaScript interface, Neon PostgreSQL, bcrypt password hashing, chess.js move validation, and a local accessible board renderer.

## Features

- Username/password signup and login.
- Bcrypt password hashing with no plaintext password storage.
- HTTP-only signed JWT session cookie.
- Legal move validation and game state from chess.js.
- A local board renderer with stable piece assets and click-to-move interaction.
- Persistent matchmaking that keeps a player in the queue until another authenticated player joins.
- Server-authoritative games with polling synchronization between both browsers.
- Server-side move validation, turn ownership, resign, draw, and automatic game completion.
- Automatic win, loss, and draw persistence after a completed game.
- Dashboard with the current board, profile, rating, and recorded statistics.
- Local tactical problems with hints and browser-local progress.
- Browser-local practice against a deterministic material-aware chess opponent; practice moves never reach the backend.
- Public read-only watching for active multiplayer games.
- Editable display name, bio, locale, rat color, rat accessory, and avatar mode.
- A full game-history view with saved final positions and move lists.
- Automatic language detection with English, Portuguese, Spanish, French, and German translations plus a language override.
- Original transparent chubby rat mascot assets for profiles and avatars.
- Render Blueprint and production Dockerfile.
- No environment files or credentials are committed.

## Existing database contract

The application expects these existing PostgreSQL tables:

- `users (id, username, password_hash, created_at)`
- `player_stats (user_id, wins, losses, draws, current_rating)`

The server does not alter these existing tables. It creates a zeroed `player_stats` row for a newly registered user when one does not already exist.

On the first authenticated profile, matchmaking, or game request, the server idempotently creates these additional application tables if they do not exist: `matchmaking_queue`, `chess_games`, `chess_game_moves`, and `user_profiles`. The Neon role used by `DATABASE_URL` must be allowed to create tables in the selected database.

`user_profiles` stores display name, bio, locale, rat color, rat accessory, and avatar mode. It is keyed by `user_id` and does not change the existing `users` or `player_stats` tables.

## Local setup

1. Install Node.js 20 or newer.
2. Install dependencies:

   ```bash
   npm ci
   ```

3. Set runtime environment variables in your shell or in a local `.env` file that is never committed:

   ```bash
   export DATABASE_URL='your exact Neon connection string'
   export SESSION_SECRET='a long random value for local development'
   export COOKIE_SECURE=false
   export PORT=3000
   ```

   Use the exact Neon connection string supplied for this project as the value of `DATABASE_URL`. The public repository intentionally contains no `.env` file and no database credential.

4. Start the server:

   ```bash
   npm start
   ```

5. Open `http://localhost:3000`.

For development with automatic restart:

```bash
npm run dev
```

## Render deployment

### Fast path with the Blueprint

1. Push or import this repository into GitHub.
2. In Render, select **New +** and choose **Blueprint**.
3. Select the `chesse` repository and apply `render.yaml`.
4. When Render asks for `DATABASE_URL`, paste the exact Neon connection string supplied for this project.
5. `SESSION_SECRET` is generated by Render. Keep `COOKIE_SECURE=true` in production.
6. Deploy. Render uses `npm ci`, starts the service with `npm start`, and checks `/api/health`.

### Manual path

Create a Render Web Service with:

- **Runtime:** Node
- **Build command:** `npm ci`
- **Start command:** `npm start`
- **Health check path:** `/api/health`

Add these environment variables in the Render dashboard:

- `DATABASE_URL`: the exact Neon PostgreSQL connection string.
- `SESSION_SECRET`: a long random value, or let Render generate it.
- `COOKIE_SECURE`: `true`.
- `NODE_ENV`: `production`.

Do not paste credentials into `render.yaml`, source files, README files, or Git history.

## API overview

- `GET /api/health` — unauthenticated service health check.
- `POST /api/auth/signup` — create an account with `username` and `password`.
- `POST /api/auth/login` — authenticate an existing account.
- `GET /api/auth/me` — return the current account and statistics.
- `POST /api/auth/logout` — clear the session cookie.
- `GET /api/stats` — return the authenticated user's statistics.
- `POST /api/games/result` — record one authenticated `win`, `loss`, or `draw`.
- `POST /api/matchmaking/join` — enter the authenticated player into the persistent queue or return an immediate match.
- `GET /api/matchmaking/status` — return `idle`, `waiting`, or `matched` state.
- `POST /api/matchmaking/leave` — leave the matchmaking queue.
- `GET /api/multiplayer/games/:gameId` — return the current server-authoritative game state and move list.
- `POST /api/multiplayer/games/:gameId/moves` — validate and submit one legal move for the authenticated player.
- `POST /api/multiplayer/games/:gameId/finish` — resign or record a draw for a participating player.
- `GET /api/profile` — return the authenticated profile, rat customization, and stats.
- `PATCH /api/profile` — update display name, bio, locale, and rat customization.
- `GET /api/profile/history` — return completed games for the authenticated player.
- `GET /api/profile/history/:gameId` — return one completed game and its saved move list.
- `GET /api/watch/games` — list active public games for spectators.
- `GET /api/watch/games/:gameId` — return an active read-only public game state.

## Security notes

The application uses parameterized SQL, bcrypt password hashes, an HTTP-only cookie, Helmet security headers, and a production-only secure cookie setting. Use a strong unique `SESSION_SECRET`. Rotate the Neon password if the connection string has ever been exposed outside a trusted secret manager.
